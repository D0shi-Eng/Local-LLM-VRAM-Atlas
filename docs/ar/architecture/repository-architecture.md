# معمارية المستودع

> المقابل الإنجليزي: [`docs/en/architecture/repository-architecture.md`](../../en/architecture/repository-architecture.md)

## الغرض

تحدّد هذه الوثيقة البنية المنشورة لمستودع «أطلس النماذج اللغوية المحلية لذاكرة
VRAM»، ومسؤولية كل مجلد، والحدود التي يجب احترامها عند التغيير.

 وهي تصف **السطح العام المنتقى**: ما يدخل التحكّم بالإصدارات، وما يُحجب منه عمدًا.

## المسؤوليات

- مجلد `schemas/` هو المرجع المُلزم: يُحسم شكل كل سجل فيه مرة واحدة، وتتبعه كل أداة
  وكل اختبار، ولا تُكرَّر القاعدة نثرًا وتُترَك للانحراف.
- مجلد `catalog/` هو المصدر القانوني: وهو مصدر الحقيقة الوحيد، وكل صفحة Markdown
  وكل عرض JSON مولَّد منه.
- أدوات `src/atlas/validation/` تتحقق من السجلات مقابل المخططات وتُخرج أخطاء مقروءة
  برموز خروج غير صفرية. وهي لا تعدّل السجلات، ولا تنزّل شيئًا، ولا تحتاج بيانات اعتماد.
- مجلد `tests/fixtures/valid/` يحوي سجلات تركيبية يجب أن تجتاز، ومجلد
  `tests/fixtures/invalid/` يحوي سجلات يجب أن تفشل لسبب موثَّق. وتحمل أسماء البيانات
  دائمًا `fixture-` حتى لا يظنها أحد بيانات فهرس حقيقية.
- مجلد `assets/branding/` يحوي هوية بصرية أصلية، ولا يظهر في الشجرة أي شعار تابع
  لطرف ثالث.

## ما هو محجوب عمدًا

توجد المسارات التالية في شجرة العمل المحلية أثناء التطوير، لكنها مستبعَدة من التحكّم
بالإصدارات عبر `.gitignore`، لأنها تاريخ هندسة داخلي أو حالة خاصة بالجهاز لا توثيق
عام:

| المسار المحجوب | السبب |
|---|---|
| `docs/phases/` | تقارير البناء الداخلية وتقارير الإغلاق والتدقيقات وجرد التسليم |
| `catalog/refresh/` | سجلات متقطعة لكل تشغيل |
| `catalog/checkpoints/` | حالة اكتشاف داخلية مؤقتة |
| `catalog/changes/` | يوم التغييرات التشغيلي |
| `catalog/release-candidate-data-manifest.json` | بيان تشغيلي يحمل مسارًا محليًا مطلقًا |
| `catalog/closure/external/bonsai-existing-server.json` | رصد جهاز المالك، بما فيه معرّف العملية والمنفذ |

ولا يلزم أيٌّ من هذه المسارات لقراءة مجموعة البيانات المنشورة أو التحقق منها أو
إعادة توليدها.

## ما هو خارج نطاق هذه البنية

- لا تُخزَّن أوزان النماذج في هذه الشجرة أبدًا؛ فالمشروع فهرس لا مستودع نماذج.
- لا أسرار ولا رموز ولا ملفات بيئة.
- لا سير عمل تكامل مستمر، ولا موقع منشور.
- لا تمثيلات متوازية للبيانات نفسها (JSON مع YAML أو Markdown أو CSV تُزامَن يدويًا).
  سجلات JSON المحقَّقة عبر JSON Schema هي مصدر الحقيقة الوحيد، وتُولَّد منها الجداول
  والصفحات.
- لا مستودع بعيد ثانٍ، ولا مرآة عامة، ولا تغيير في الرؤية؛ فهذه ليست جزءًا من عقد
  المستودع.

## حدود التغيير

يمكن للاكتشاف واستخراج البيانات الوصفية وبوابة الترخيص وفحوص بيئات التشغيل
وتصنيف الذاكرة الرسومية والمراجعة (انظر [`data-flow.md`](data-flow.md)) أن تضيف
وحدات جديدة، لكن عليها استهلاك `schemas/` و`src/atlas/validation/` بدل إعادة تعريف
أشكال السجلات أو إعادة تنفيذ التحقق. وأي تغيير في شكل سجل يمرّ عبر المخطط أولًا ومعه
الاختبارات.

وتخضع تغييرات التوثيق للضبط نفسه بالمقلوب: لكل وثيقة إنجليزية مقابل عربي،
ويُفرض تطابق بنية العناوين بينهما باختبار آلي.
