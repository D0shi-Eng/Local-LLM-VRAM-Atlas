# التحديث واستيعاب الأدلة

> المقابل الإنجليزي: [`docs/en/workflows/refresh-and-evidence-ingestion.md`](../../en/workflows/refresh-and-evidence-ingestion.md)
>
> المخططات معروضة في الوثيقة الإنجليزية عن قصد، لوضوح المصطلحات الهندسية.
> ولكل شكل شرح عربي في [فهرس الأشكال](../../diagrams/README.md).

## النطاق

تغطي هذه الوثيقة سير العمل الذي ينقل واقعًا خارجيًا إلى الأطلس:

1. **اكتشاف المصدر واستقباله المضبوط**
2. **تحليل البنية والذاكرة والتكميم**
3. **استيعاب أدلة الجودة**
4. **تدفّق أدلة الاحتفاظ والذاكرة الرسومية**

كل سير عمل في هذه الوثيقة **محدود، ومجهول الهوية، للقراءة فقط بالنسبة للمصدر**،
**وتجرياته افتراضيًا** بالنسبة للكتالوج المحلي.

---

## سير العمل أ — اكتشاف المصدر والاستقبال المضبوط

### الشكل ٣ — من الاكتشاف إلى السجل المعياري

المخطط بالإنجليزية في
[refresh-and-evidence-ingestion.md](../../en/workflows/refresh-and-evidence-ingestion.md).

### القواعد

- الرفض يُنتج **سجل رفض**، لا استثناءً ولا تخطيًا صامتًا. وغياب سجل الرفض يجعل
  البحث المحدود غير قابل للتمييز عن بحث لم يُنتهِ.
- لا تُقرأ بيانات الاعتماد ولا تُخزَّن ولا تُنقل في أي لحظة.
- تُرفض روابط أوزان النماذج **قبل** إجراء أي طلب شبكي.
- لا تُتبع إعادة التوجيه.
- لا يُعدَّل الكتالوج القانوني أبدًا دون `--apply` صريح.

---

## سير العمل ب — تحليل البنية والذاكرة والتكميم

### الشكل ٤ — من البيانات المصرَّح بها إلى مدى ذاكرة

المخطط بالإنجليزية في
[refresh-and-evidence-ingestion.md](../../en/workflows/refresh-and-evidence-ingestion.md).

### القواعد

- **المدى ليس حكمًا.** يستهلك المصنِّف مدىً مع حالة دليل، ويُخرج حكم فئة قد يكون
  `insufficient_evidence` عن قصد.
- **البُعد الناقص يبقى ناقصًا.** إذا لم يُحلَّل عدد رؤوس المفتاح-القيمة، تبقى
  بايتات KV غائبة، لا صفرًا.
- **لا ثابت عبء مخترَع.** إذا لم ينشر وقت التشغيل حدًّا ساكنًا أو ديناميكيًا لعبء
  الذاكرة الرسومية، بقي الحدّ الأعلى غائبًا ولا يُستعاض عنه بأي رقم. هذه القاعدة
  الواحدة هي سبب إبلاغ الأطلس حاليًا عن صفر ملاءمة صارمة، وهي نتيجة مقصودة لا
  ثغرة تُسدّ بالتخمين.
- **حجم الملف ليس استهلاك الذاكرة.** بايتات الأوزان حدٌّ في المعادلة، وليست
  الجواب.

---

## سير العمل ج — استيعاب أدلة الجودة

### الشكل ٥ — من نتيجة منشورة إلى محور جودة

المخطط بالإنجليزية في
[refresh-and-evidence-ingestion.md](../../en/workflows/refresh-and-evidence-ingestion.md).

### القواعد

- **درجة الإصدار الأساسي لا تُنقل أبدًا إلى مشتق مكمَّم.** المُخرَج المكمَّم بعد
  التدريب الذي لا يحمل نتيجة دقيقة هو `unevaluated`، لا «تقريبًا بدرجة الأساسي».
- **متغيّر المحاذاة لا يرث درجة أبيه أبدًا.**
- **دليل الناشر يُسجَّل، ويُوسم بأنه دليل ناشر.** وهو لا يفي ببوابة تعدّد المصادر
  المستقلة أبدًا.
- **ادعاء تعدّد اللغات ليس دليلًا على العربية.** يبقى محور الجودة العربية
  `unknown` حتى توجد نتيجة عربية مخصّصة.
- **يُحسب الاستقلال لكل تشغيل**، بمفتاح يضم المقيِّم والاختبار وإصداره وإصدار
  مجموعة الأدوات وتاريخ التقييم والمقياس، حتى لا تنتج إعادة النشر مظهر تعدّد
  المصادر.

---

## سير العمل د — تدفّق أدلة الاحتفاظ والذاكرة الرسومية

### الشكل ٦ — مسارا دليل لا يجوز الخلط بينهما

المخطط بالإنجليزية في
[refresh-and-evidence-ingestion.md](../../en/workflows/refresh-and-evidence-ingestion.md).

### القواعد

- **الاحتفاظ والملاءمة سؤالان مختلفان.** الاحتفاظ يسأل هل أضعف التكميم الجودة،
  والملاءمة تسأل هل يعمل المُخرَج على سعة معيّنة. ولا يستنتج أحدهما الآخر.
- **قابلية المقارنة كلٌّ أو لا شيء.** إذا اختلف أي مفتاح من مفاتيح الإعداد
  القابل للمقارنة، لا يُحسب أي فرق، ويقول السجل ذلك صراحةً.
- **حدّ النطاق يرافق السجل ولا يُسقَط.** قياس عند سياقبطول  100 ألف رمز ليس قياس
  ملاءمة عند السياق الأساس، والسجل يقول ذلك حرفيًا.
- **العتاد لا يُغني عن السعة.** قياس على عتاد أكبر من الفئة المستهدَفة دليل على
  متطلّبات الذاكرة، لا التحقق من عمل المُخرَج على الفئة الأصغر.

## تشغيل هذه السِيَر

كل سير عمل أعلاه معرَّض عبر أداة واحدة، تعمل في وضع تجريبي افتراضيًا:

```bash
python -m atlas.cli.main discover candidates          # Announcement passes المضبوطة
python -m atlas.cli.main discover delta              # الاكتشاف التدريجي المحدود
python -m atlas.cli.main refresh plan                # خطة تجريبية
python -m atlas.cli.main refresh status              # نقاط التحقق، والطابور، واليوم
python -m atlas.cli.main refresh apply --plan <file> # تطبيق ذرّي
python -m atlas.cli.main quality sources --check     # سجل مصادر الجودة
python -m atlas.cli.main quality gaps                # نطاقات الأدلة الناقصة
python -m atlas.cli.main retention show <model_id>   # الاحتفاظ عند التكميم
python -m atlas.cli.main closure evidence            # إعادة استحواذ النسب الحالية
python -m atlas.cli.main closure vram                # حالات ملاءمة الفئات
python -m atlas.cli.main closure readiness           # جاهزية النشر
```

## عقد رموز الخروج

تستخدم واجهة التحديث عقدَ رموز خروج موثَّقًا، ليستطيع المستدعي أن يميّز بين
«لا تغييرات» و«شيء يحتاج تدخّلًا بشريًا».

| الرمز | المعنى |
|---|---|
| `0` | نجاح: لا تغييرات، أو معلوماتية فقط. |
| `10` | عُثر على تغييرات: الخطة تحتوي عمليات. **وهذه هي النتيجة المتوقَّعة لتخطيط ناجح، وليست خطأ.** |
| `11` | يلزم مراجعة: تغييرات حرجة أو واسعة الأثر قيد المراجعة. |
| `12` | تشغيل جزئي: نفدت ميزانية الطلبات، وحُفظت الحالة. |
| `13` | فشل مصدر خارجي، وبقيت نقاط التحقق محفوظة. |
| `14` | رفض خطة قديمة: تحرّك الكتالوج بعد بناء الخطة. |
| `15` | فشل معاملة، وقد تُرجعت التغييرات. |
| `16` | يلزم استرجاع: وُجدت علامة معاملة غير مكتملة. |
| `17` | حجب أمني: رابط أو حمولة أوزان أو محاولة مصادقة غير آمنة. |
| `18` | إدخال غير صالح: وسائط خاطئة، أو فشل تحقق، أو ملف خطة غير قابل للقراءة. |

ولأن الرمز `10` إشارة نجاح، ينبغي للسيناريوهات أن تختبر `0` **أو** `10` عند
اكتفائها بمعرفة أن التخطيط نجح.
