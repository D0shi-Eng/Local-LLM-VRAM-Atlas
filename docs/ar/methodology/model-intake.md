# استقبال النماذج

> المقابل الإنجليزي: `docs/en/methodology/model-intake.md`

## النطاق

استقبال النماذج يحوّل لقطات عامة مجهولة مقتصرة على البيانات الوصفية إلى
سجلات أطلس معيارية. لا ينزّل الأوزان أبدًا، ولا يشغّل النماذج، ولا يسند
طبقات VRAM، ولا يرتّب، ولا يخترع القيم المفقودة.

## ترتيب المراحل

```text
المعرف العام → حل المصدر → جلب البيانات → حل المراجعة
→ حد البيانات الخام → التطبيع → تقييم المصدر والرسمية
→ استخراج الترخيص → استخراج البنية → جرد الملفات
→ حل النسب → بناء الأدلة → بناء السجل → التحقق → الحفظ
```

كل مرحلة تفشل بصوت عالٍ بدل إنتاج سجل مضلل.

## الحدود

البيانات الخام الخارجية (`RawModelMetadata`) لا تعبر إلى النطاق أبدًا:
يترجمها المطبّع إلى سجل معياري، ولا تتسرب أصناف SDK الخاصة بالمصدر خارج
المحول. الحقول الخاصة بالمنصة التي لا بيت معياري لها (وسوم المسار، وأسماء
المكتبات، وقوائم الملفات) تبقى في ملاحظات الأدلة لا في مخطط النموذج.

## التجربة الجافة أولًا وكتابة ثابتة النتيجة

الأمر `atlas intake <repo>` تجربة جافة افتراضيًا: يجلب ويبني ويتحقق ويطبع
ملخصًا دون كتابة. خيار `--write` يحفظ بعد التحقق فقط وبصورة ذرية (ملف
مؤقت ثم استبدال). إعادة نفس `المستودع + المراجعة المحلولة` ثابتة النتيجة؛
والمراجعة المتغيرة ترفض الاستبدال الصامت دون `--allow-update`.

## الحالات

`discovered` و`pending_metadata` و`pending_license` و`pending_lineage`
(تُسجل كـ`pending_metadata` في السجل — انظر تقرير التوافق) و`metadata_verified`
(تُسجل كـ`experimental` أي موثقة حسب السياسة، وليست `recommended` أبدًا)
و`blocked` و`rejected`. كلمة `verified` هنا تعني سلامة النسب والبنية لا
الجودة ولا السرعة ولا الملاءمة لبطاقة رسومية.
