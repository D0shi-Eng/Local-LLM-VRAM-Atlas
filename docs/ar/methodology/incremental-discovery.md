# الاكتشاف التدريجي (المرحلة الخامسة)

عند الطلب فقط. لا خدمة خلفية، لا مراقبة مستمرة، لا خادم، لا مجدول.

## مرحلتان

**المرحلة أ — فحص خفيف.** لكل مستودع معروف، تُجلب فقط الهوية والبصمة
المراجعية (`sha`) وتاريخ التعديل وحالة التقييد عبر
`model_info(..., files_metadata=False, token=False)`. تُقارن البصمة مع آخر
مراجعة موثقة. تطابق البصمة يعني عدم إعادة البناء: مرور الوقت وحده لا يستدعي
إعادة الجلب.

**المرحلة ب — تحديث مفصّل.** فقط للمرشحين الجدد أو المتغيرين أو المحتاجين
لإعادة تحقق: البيانات الوصفية المنظمة وبيانات الملفات عبر خط الأنابيب الآمن
الموجود، مع حدود صارمة لحجم كل مستند وإجمالي الحمولة.

## نافذة حديثة مع تداخل

يدعم عميل Hub المثبت `list_models(..., sort="last_modified")`. لا يُفترض اتجاه
الترتيب ولا استقرار الصفحات عند تساوي الطوابع ولا وجود مؤشر "منذ" من الخادم.
لذلك تسرد كل استراتيجية أحدث النماذج ضمن حد ثابت، ثم تُطبق محليًا:
مرشح التداخل، إزالة التكرار، التمييز بين المعروف والجديد، ثم فحص المراجعات.
نافذة التداخل (يومان) تمتص انحراف الساعات وعدم استقرار الطوابع المتساوية دون
تكرار الأحداث.

## الميزانيات والحدود

كل استدعاء يدوي: 150 طلبًا كحد أقصى، 25 مرشحًا جديدًا مفصّلًا (الباقي يُؤجل
ولا يُسقط)، 120 مرشحًا إجمالًا، تنفيذ متسلسل. نفاد الميزانية يوقف التشغيل
بنظافة مع حفظ نقاط التوقف والطابور المؤجل. تحديد المعدل يُحفظ ويتوقف دون
تدوير هويات أو بيانات اعتماد، والدخول مجهول دائمًا.

## نقاط التوقف

علامة مستقلة لكل (استراتيجية، مصدر، مزود) تحت `catalog/checkpoints/`، وليست
داخل سجلات النماذج. المصدر الفاشل لا يتقدم. الحقول: المعرفات، المزود، آخر
تشغيل ناجح، العلامة المزودية، بداية التداخل، آخر هوية ومراجعة، حالة الاستمرار،
والحالة.

## الاكتشاف ليس تأهيلًا

الشعبية (التنزيلات والإعجابات والترتيب) إشارات اكتشاف فقط. كل مرشح جديد يمر
عبر تأهيل المرحلة الرابعة دون ترقية تلقائية. أولوية المعالجة (مصدر موثوق،
حداثة، صلة بـ 4–16GB) ليست ترتيب جودة.

## الصلة

أولوية للمرشحين المحتملين لأجهزة 4/8/12/16GB (كثيفة صغيرة، MoE، بت منخفض
أصلي، ضغط قوي، متغيرات مكممة). النماذج الضخمة غير ذات الصلة لا تُجمع لمجرد
حداثتها. النماذج المقيدة تُعالج ببيانات مجهولة فقط دون طلب وصول.
