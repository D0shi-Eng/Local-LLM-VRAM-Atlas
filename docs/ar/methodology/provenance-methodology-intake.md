# منهجية النسب والمصدر — سجلات الاستقبال

> المقابل الإنجليزي: `docs/en/methodology/provenance-methodology-intake.md`

## ما يُسجل لكل استقبال

كل استقبال يحفظ: المنصة (`hugging-face`)، ومعرف المستودع حرفيًا (دون
تصغير مدمر — المفتاح المطبّع منفصل)، والنطاق والمالك، ورابط المصدر،
والمراجعة المطلوبة (`main`)، والمراجعة الثابتة المحلولة (SHA) مع طابع
الاسترجاع (ISO 8601 بتوقيت UTC)، ونوع مصدر البيانات، وحالة ادعاء الناشر،
وحالة التحقق.

## أين يُحفظ

السجل المعياري لا يحمل حقول نسب حرة (مخططه يمنعها)، لذا يعيش النسب في
سجلات مرتبطة: سجل مصدر لكل مستودع (مع `revision` وملاحظة صريحة
`officiality_status=unverified`) وسجل دليل لكل حقل حساس — الترخيص،
والانفتاح، والنموذج الأساس، والبنية، وعدد المعاملات، والسياق، والتكميم،
والشعبية، والمراجعة المحلولة. وحقل `verification.evidence_ids` يربطها معًا.

## أدلة لكل حقل وحفظ التعارض

قد تأتي الحقول من أدلة مختلفة لذا يكون النسب لكل حقل لا للنموذج كله. عند
تعارض المصادر يُحتفظ بالطرفين مع حالة `conflict_detected`/`unresolved` —
فالأولوية لا تخفي التعارض بصمت أبدًا.

## المراجعات

`main` طلب وليست هوية. `الناشر/النموذج@مراجعة-A` و`@مراجعة-B` هويتان
زمنيتان مميزتان. المراجعة المحلولة الجديدة لا تستبدل السجل القديم بصمت؛
وبدون `--allow-update` يرفض خط الأنابيب. وإذا لم يعد المصدر مراجعة ثابتة
يبقى `resolved_revision` فارغًا مع حالة `unverified`.
