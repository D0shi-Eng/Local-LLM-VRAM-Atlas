# إغلاق الأدلة

> المقابل الإنجليزي: [`README.md`](README.md)

## معنى «الإغلاق» هنا

**«الإغلاق» مصطلح مجالي، لا تسمية لمرحلة تطوير.** ويسمّي به المشروع نشاطًا
هندسيًا واحدًا محدَّدًا:

> إرفاق مزيد من الأدلة *الصادقة والقابلة للتتبع والمرتبطة بإصدار محدَّد* بمجموعة
> محدودة من المُخرجات الفعلية، لتصبح الجاهزية قابلة للحكم على الأدلة لا على
> الافتراض.

وهو اللفظ نفسه المستعمل في «إغلاق خلل» و«إغلاق فجوة دليل» و«الإغلاق الطوبولوجي»:
إيصال مجموعة محدودة إلى حالة محسومة، مع التصريح بما لم يُحسم.

**الإغلاق ليس التكامل.** المُخرَج المُغلق هو الذي حُسمت فيه سؤال الأدلة، وقد يكون
مُغلقًا ومع ذلك في حالة `CATALOG_ONLY`. ولا يدّعي هذا المجلد وجود أي توصية.

## سبب وجود المجلد

الإغلاق موجود لأن الإجابة عن «هل يمكنني تشغيل هذا على بطاقة 4 غيغابايت؟» تتطلب
ضمّ خمسة نطاقات منفصلة، كل منها ناقص بذاته:

1. **هوية المُخرَج الدقيقة** — أي ملف، عند أي مراجعة
2. **النسب الحالي** — هل زال السجل يصف واقع المصدر
3. **البنية** — هل الأبعاد الحاسمة محلولة بما يكفي لحساب أي شيء
4. **الجودة المستقلة** — هل توجد نتيجة مقيسة لهذا المُخرَج بالذات
5. **الاحتفاظ عند التكميم** — كم كلّف التكميم، تحت أدوات قابلة للمقارنة

ولا يملك أي نظام فرعي هذه الخمسة معًا. والإغلاق هو الموضع الذي تُضمّ فيه مرة
واحدة، تحت سياسة معلَنة واحدة، حيث تُسجَّل الإجابة المركَّبة.

## المحتوى

| المسار | المحتوى |
|---|---|
| `core-recommendation-set.json` | مجموعة التوصيات الأساسية: 19 مرشَّحًا محدودًا بفئاتهم المستهدفة، مع إشارات الاختيار المستبعَدة عمدًا |
| `readiness.json` | جاهزية النشر لكل مرشَّح ولكل فئة: أربع حالات، وتسع بوابات صارمة، وذكر كل بوابة ناقصة |
| `quant-retention-closure.json` | الاحتفاظ عند التكميم لكل مرشَّح أساسي، ولا يُحسب إلا عند تطابق مفتاح الإعداد القابل للمقارنة |
| `vram/` | سجل أدلة ذاكرة واحد لكل مرشَّح أساسي ولكل فئة، مع حدود النطاق مرفقة |
| `current-evidence/index.json` | أدلة نسب حالية أُعيد استحواذها لسجلات المجموعة الأساسية |
| `external/` | أدلة خارجية مُطبَّعة: نتائج المصادر، وفهرس القياسات، والاحتفاظ، ونتائج الهوية، ونتيجة عبء وقت التشغيل، وشروط الأدلة المقروءة آليًا |

## عقد السياسة

يحمل `readiness.json` السياسة بوصفها بيانات لا شيفرة:

```text
policy_id:   atlas-closure-readiness
policy_kind: publication_readiness
states:      STRICT_READY, CANDIDATE_READY, CATALOG_ONLY, BLOCKED
strict gates: 9
```

ولا تُدمج الحالات الأربع أبدًا، ولا يُمنح تنازل لأي بوابة، ولا يوجد تجاوز يدوي.

ويظهر المفرد نفسه في
[`recommendation-result.schema.json`](../../schemas/recommendation-result.schema.json)،
فلا يحتاج القارئ إلى معرفة أي نظام فرعي كتب السجل.

## النتيجة الحالية

| الحالة | العدد |
|---|---|
| `STRICT_READY` | 0 |
| `CANDIDATE_READY` | 6 |
| `CATALOG_ONLY` | 12 |
| `BLOCKED` | 1 |

صفر توصيات صارمة عند 4 و8 و12 و16 غيغابايت. والمُعيقان الحاسمان موثّقان لا
مجهولان: بيئات التشغيل لا تنشر حدًّا لعبء الذاكرة الرسومية، ولا توجد نتيجة جودة
مستقلة متعددة المصادر لأي مُخرَج أساسي.

انظر [جاهزية التوصيات](../../docs/ar/workflows/recommendation-readiness.md)
لدلالات البوابات، و[منهجية إغلاق الأدلة](../../docs/ar/methodology/evidence-closure-methodology.md)
للمنهجية الكاملة.

## إعادة التوليد

```bash
python -m atlas.cli.main closure core-set        # بناء مجموعة التوصيات الأساسية
python -m atlas.cli.main closure evidence        # إعادة استحواذ النسب الحالية
python -m atlas.cli.main closure vram            # حالات الملاءمة لكل مرشَّح
python -m atlas.cli.main closure readiness        # جاهزية النشر
python -m atlas.cli.main closure gap-matrix      # مصفوفة فجوات الأدلة
python -m atlas.cli.main closure views --apply   # العروض ثنائية اللغة EN/AR
```

كل أمر يعمل في وضع تجريبي افتراضيًا. وأمر `closure evidence` هو الأمر الوحيد في
هذا المشروع الذي يجري طلبات شبكية: محدودة، ومجهولة الهوية، وللقراءة فقط.

## ملف مستبعَد

يسجّل `external/bonsai-existing-server.json` رصدًا لبيئة تشغيل محلية قائمة على
جهاز المالك، بما فيه معرّف العملية والمنفذ، ولذلك يستبعده `.gitignore` من التحكّم
بالإصدارات. أما خصائص الأمان العامة التي أثبتّها فهي مغطّاة في
[`test_local_server_safety.py`](../../tests/security/test_local_server_safety.py).
